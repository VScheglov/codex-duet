# codex-duet

Ревью, в котором Claude и Codex договариваются сами. Codex находит замечания, Claude по каждому либо исправляет, либо возражает с доказательствами, либо откладывает для тебя. Цикл продолжается, пока они не согласятся, не упрутся в тупик или не кончатся раунды. Копировать текст между чатами не нужно.

Работает и в обратную сторону: в режиме **build** код пишет Codex, а Claude работает архитектором и ревьюером. Так тратится в основном лимит Codex.

## Установка

Нужны:

- Claude Code 2.1.275 или новее;
- [Codex CLI](https://github.com/openai/codex), в котором выполнен вход: `codex` в `PATH` (другой бинарник задаёт `CODEX_DUET_CODEX_BIN`);
- Node.js 22 или новее: раннер запускается как `node scripts/duet.mjs`;
- git для режимов code и build.

В терминальной сессии Claude Code:

```
/plugin install codex-duet --marketplace VScheglov/codex-duet
```

На вопрос `Add marketplace?` ответь `y` и выбери область: с user плагин работает во всех проектах. То же из оболочки:

```bash
claude plugin install codex-duet --marketplace VScheglov/codex-duet
```

В приложении Claude, где `/plugin` не работает, нажми + рядом с полем ввода, затем Plugins, Add marketplace с `VScheglov/codex-duet` и Add plugin.

Если `/codex-duet` и `/duet` после установки не видны, открой новую сессию или выполни `/reload-plugins`. Полное имя команды скилла `/codex-duet:codex-duet`, короткое `/codex-duet` работает, пока это имя не занято другой командой.

**Рекомендуется: 12 часов на фоновую команду.** Ход Codex идёт долго, поэтому Claude запускает его в фоне с `timeout: 43200000`. Без настройки Claude Code обрежет это до 2 часов, и долгий ход оборвётся (продолжить его можно через `retry`). Чтобы этого не случалось, добавь в `~/.claude/settings.json`:

```json
{ "env": { "BASH_MAX_TIMEOUT_MS": "43200000" } }
```

Настройка действует в сессиях, открытых после правки.

## Язык

Настройка плагина `language` принимает `auto` (по умолчанию), `en` (английский), `ru` (русский) или `zh` (упрощённый китайский). В режиме `auto` берётся первая непустая переменная окружения из `LC_ALL`, `LC_MESSAGES`, `LANG`, именно в этом порядке: значение, начинающееся с `ru`, выбирает русский, с `zh` — китайский, любое другое — английский.

Только если все три переменные не заданы или пусты, на macOS берётся первый предпочитаемый язык из `AppleLanguages` с тем же правилом для `ru` и `zh`. Непустая переменная локали всегда имеет приоритет. На других платформах, при пустом списке предпочитаемых языков или ошибке чтения используется английский.

Чтобы выбрать русский из оболочки:

```bash
echo '{"language":"ru"}' | claude plugin configure codex-duet --values-stdin
```

Вместо `ru` можно указать `en`, `zh` или `auto`. `--values-stdin` читает JSON-объект со значениями в виде однострочных строк; неуказанные настройки сохраняют текущие значения. Без `--values-stdin` команда `claude plugin configure codex-duet` только показывает конфигурацию. Изменить язык также можно в строке плагина в меню `/plugin`.

При смене настройки модуль перезагружается. Настройка действует на интерфейс плагина и его заметки и сообщения для Claude; вывод раннера остаётся английским.

## Где работает

| Платформа | Что |
|---|---|
| macOS | всё |
| Linux | всё, кроме звука: у Claude Code на Linux нет проигрывателя, тосты и строка остаются. Блокировку сессии, оставшуюся от раннера, который убили через `kill -9` или который упал вместе с машиной, снимаешь руками: ошибка `stale lock` называет файл. На macOS ядро снимает такую блокировку само (`O_EXLOCK`) |
| Windows | не поддерживается: раннер и мод вызывают `kill`, `tail`, `head`, `grep` и `diff`. WSL должен вести себя как Linux, но не проверялся |

Если Claude Code управляется организацией (managed settings), хук `Stop` не запускается в плагинах, которые человек ставит сам. Тогда мод не возвращает Claude в цикл, когда тот закончил ход (см. «Цикл не останавливается сам»). Остальное работает.

## Использование

```
/codex-duet plan                      план из plan mode или из текущего разговора
/codex-duet code                      незакоммиченные изменения (вместе с untracked)
/codex-duet code --base main          вся ветка от merge-base с main
/codex-duet file docs/spec.md         любые файлы: тест-кейсы, SQL, спеки, конфиги
/codex-duet code -- проверь миграции  после `--` идёт фокус ревью
/codex-duet status                    где мы сейчас (пригодится и после сжатия контекста)
```

Можно и словами: «отдай Codex на ревью», «обсудите с Codex план».

Опции: `--max-rounds N` (по умолчанию 10), `--model`, `--effort` (по умолчанию из `~/.codex/config.toml`; модель можно назвать словами: «делегируй Codex, модель астра, уровень max»), `--timeout-min` (лимит на ход Codex; по умолчанию без ограничения), `--sandbox` (по умолчанию `inherit`: как в твоём Codex; `read-only` по желанию).

Модель и уровень раннер сверяет с кешем моделей твоего Codex (`~/.codex/models_cache.json`). Он откажет до запуска и перечислит доступное, если:

- такой модели нет (можно указать ID `gpt-6-astra` или название `GPT-6-Astra`);
- такого уровня нет;
- модель не поддерживает уровень, в том числе тот, что стоит по умолчанию в `config.toml`.

Если кеша нет, проверка пропускается. Сменить модель или уровень посреди сессии можно, добавив `--model`/`--effort` к `reply`, `review` или `retry`. Строка `Model:` в сводке раунда показывает, на чём идёт сессия.

**⚡ Fast.** Отдельного флага нет: режим скорости Codex берёт из `config.toml` (`service_tier = "priority"`: так Fast называется в каталоге моделей). Значок ⚡ в строке над вводом, в списке задач и в панели («Модель: … · ⚡ Fast») появляется, только когда известно, что ход идёт в Fast. Пометка «(из конфига)» значит, что Fast включён в конфиге, а в каталоге моделей он есть у этой модели. Пометка пропадает, когда Codex сам записывает режим хода в журнал треда (`~/.codex/sessions/…/rollout-…-<тред>.jsonl`, запись `thread_settings_applied`). Если журнал показал обычный режим, значок снимается. Codex 0.160 делает такую запись в начале каждого продолженного хода, а в первом ходе нового треда её может не быть.

**Время.** Ход Codex идёт долго, build — особенно, поэтому Claude запускает `start`, `reply`, `review` и `retry` в фоне с `timeout: 43200000` (12 часов). Потолок фоновой команды в Claude Code — 2 часа, если его не поднять: `max(2 ч, BASH_MAX_TIMEOUT_MS)`. Как поднять до 12 часов, сказано в «Установке»; эта настройка заодно поднимает до 12 часов и предел тайм-аута для команд на переднем плане. Тайм-аут выше потолка Claude Code молча обрезает до потолка. На переднем плане команда без явного `timeout` живёт 2 минуты, в фоне — 30. Своего лимита на ход у раннера по умолчанию нет, задать его можно через `--timeout-min N`. Сессии, начатые до 0.6.0, хранят старый лимит в 60 минут; снять его можно командой `retry --timeout-min 0` (или с `reply`/`review`).

**Оборванный ход.** Если ход оборвался после того, как Codex начал работу (кончилось время фоновой команды, нажали «Стоп», Codex упал), `retry` продолжает тот же тред Codex с коротким промптом «продолжи с того места», даже в первом раунде. Сделанная работа и прочитанное остаются у Codex в контексте. Продолжить можно, пока цел журнал треда в `~/.codex/sessions`; если его нет, ход начинается заново. `retry --fresh` начинает заново в любом случае.

**Несколько задач сразу.** Можно делегировать сразу несколько задач: у каждого build свой worktree и своя ветка. Одновременно на машине идут не больше десяти ходов Codex (`CODEX_DUET_MAX_PARALLEL`), остальные ждут в очереди (фаза `queued`) в порядке постановки и стартуют сами, как освободится слот. Каждый ход Codex поднимает все MCP-серверы из конфига и тратит одну квоту, поэтому без очереди десять задач — это сотни процессов. Слот держится только пока работает Codex; пока Claude ревьюит, он свободен. Ожидание в очереди засчитывается в двухчасовой потолок фоновой команды, так что лучше ставить по несколько задач, а не десятки сразу.

## Режим build: Codex пишет, Claude ревьюит

```
/codex-duet build                     «делегируй Codex …», «пусть Codex реализует …»
```

1. Claude пишет спецификацию: цель, границы, ограничения, критерии приёмки, как проверять.
2. Раннер создаёт ветку `codex-duet/<id>` в отдельном worktree от HEAD. Твоё рабочее дерево не трогается. Незакоммиченное Codex не видит.
3. Codex реализует, гоняет тесты и отчитывается: что сделал, что проверил, что под вопросом.
4. Claude смотрит дифф раунда, сам запускает тесты в worktree и поднимает замечания C1…Cn. Codex исправляет или возражает. Политика остановки та же, тупики приходят к тебе (и в панель `/duet`).
5. Когда всё сошлось, с твоего согласия `finish` коммитит работу в ветку и убирает worktree, а сливаешь ты сам. `discard` удаляет и worktree, и ветку.

Подробности для Claude лежат в `references/build.md`.

## Режим audit: Codex проверяет, ничего не меняя

```
/codex-duet audit                     «проведи аудит через Codex …», «пусть Codex проверит … и даст отчёт»
```

Разовый отчёт без переговоров: аудит кода, данных, эталона, политики. Поэтому Claude не тратит токены на ответ по каждому замечанию. Если эталон нельзя править без твоего `APPROVED`, ревью здесь не подходит: почти всё ушло бы к тебе. Не подходит и build: аудит ничего не должен менять.

1. Claude пишет задание: что проверить и на какой вопрос ответить, границы, что считать находкой, что вынести в заметки (рейтинг, таблицу).
2. Codex работает прямо в папке проекта, всегда в песочнице read-only: `--sandbox` с другим значением раннер не примет. Промпт запрещает и записи через MCP-инструменты, а это защита на уровне инструкции, не песочницы (см. «Безопасность»).
3. Один ход. На выходе итог, находки A1…An (важность, место, доказательства, рекомендация, уверенность) и что проверено, а что нет. В сводке Claude видит по строке на находку, всё остальное лежит в `report.md` сессии.
4. Отвечать не на что: `reply` и `review` для аудита отказывают. Нужен другой угол — новый аудит с более точным заданием. Находки остаются утверждениями Codex: перед тем как на них опираться, Claude проверяет нужные или говорит, что они не проверены.

Очередь, панель (`/duet` показывает итог и находки), ⚡ Fast, 12 часов на ход и `retry` с продолжением оборванного треда работают так же, как в остальных режимах.

## Как идут переговоры

```
start ─► Codex: замечания C1…Cn (JSON по схеме)
          │
          ▼
   Claude по каждому замечанию:  fixed · disputed · needs-user
          │
reply ─► Codex (та же сессия, resume): resolved · withdrawn · open + контраргумент · новые
          │
          ▼
   scripts/policy.mjs → continue · done · escalate (тупик → тебе)
```

- У каждого замечания постоянный ID. Codex видит ответы Claude и diff между раундами.
- Если ты решил спор в пользу текущей версии (`owner-decided`), замечание закрывается, даже если Codex с этим не согласен.
- Когда раунды кончаются, всегда происходит эскалация, что бы ни сказала политика.
- Claude ничего не коммитит.

## Политика остановки (`scripts/policy.mjs`)

Правила проверяются сверху вниз, срабатывает первое подходящее:

1. Claude отложил решение с severity critical/high (`needs-user`) → **escalate** сразу.
2. Codex говорит `approve`, открытых critical/high нет → **done**. Medium/low уходят в отчёт, остальное отложенное приносится тебе.
3. Codex 2 раза отклонил возражения по одному замечанию → **escalate** (тупик).
4. Два раунда подряд открытых замечаний не становится меньше → **escalate** (застой).
5. Иначе → **continue**.

Пороги задаются константами `MAX_DISPUTES` и `STALL_ROUNDS`. Если меняешь правила, поправь и тесты `policy …` в `tests/run.mjs`.

## Панель `/duet` и защита

В плагине есть мод Claude Code (`hooks/register.tsx`). Раз в 2 секунды он читает файлы сессий и показывает ревью, которое ведёт **эта** сессия Claude: раннер записывает в состояние, из какой сессии Claude его вызвали (`CLAUDE_CODE_SESSION_ID`), и при каждом ходе обновляет. Продолжишь ревью из другой сессии — первый же `reply` или `retry` переведёт его туда. Чужое ревью видно только в панели `/duet`, с пометкой и без кнопок решений; строки, футера, тостов и звуков от него нет. Ревью, начатые до 0.6.0, без отметки владельца, показываются везде, как раньше.

| Где | Что |
|---|---|
| **Панель** `/duet` | при нескольких задачах — список сверху (⏳ идёт, ⏸ в очереди с местом, 🙋 нужен ты, ✅ готово; таймер, модель), строка открывает подробности задачи; дальше этап и таймер раунда; модель и уровень хода, ⚡ Fast, если ход идёт в Fast; «Сейчас: …» — команда Codex или «думает N мин», если поток его событий молчит больше двух минут, и «журнал Codex обновлён N с назад»: журнал треда растёт, даже когда Codex думает молча; последние слова Codex целиком, с абзацами, списками и `кодом` (рисуются как markdown), с возрастом, если они старше двух минут, и его действия («запускает тесты …», «запускает скрипт Python»); его план; доска замечаний (● открыто, ⏸ отложено, ✓ исправлено, ↩ снято, ⚔×N споров) с полосой «закрыто N из M»: заголовки переносятся под себя, а не обрезаются, ▸ у замечания разворачивает, что сказали обе стороны, закрытые свёрнуты, пока есть открытые; табло и история раундов; кнопка «Стоп» (останавливает и ход в очереди); внизу свёрнутые «Настройки». Текст панели переносится по ширине, обрезаются только строки списка задач и команд Codex |
| ↳ при эскалации | позиции Codex и Claude и кнопки [Прав Codex] / [Прав Claude], затем «Отправить решения Claude» |
| **Строка над промптом** и статус-строка | этап, таймер, текущее действие Codex; строки других модов остаются под ней |
| **Футер** | метка вроде «Duet r3 ⏳ 4:12», по нажатию открывает панель; видна, даже если строка над промптом выключена |
| **Тосты** | начало и конец раунда, эскалация, сбой; после раунда подсказка «продолжай codex-duet» (Tab) |
| **Звук** | эскалация (нужно твоё решение), конец ревью, сбой раунда или пропавший процесс Codex; ходы Claude звука не дают. Звучат штатные сигналы приложения Claude: `tool_approval_needed`, `enter_voice_mode`, `disconnected`. Они играют прямо из приложения и в плагин не копируются. Без приложения звучат запасные из `sounds/` |

**Цикл не останавливается сам.** Если сессия ждёт хода Claude (ответить на замечания или в build проверить раунд Codex), а Claude закончил ход, мод один раз возвращает его в цикл через хук `Stop`. Он не делает этого, если:

- Claude задал тебе вопрос;
- ты написал сообщение, и Claude ответил на него, не трогая цикл;
- идёт фоновая задача или запланировано пробуждение сессии;
- сессия ждёт твоего решения (эскалация);
- Claude только что уже возвращали.

Возврат и сводка работают только в той сессии Claude, которая ведёт ревью.

Пока идёт code-ревью или build (активными они считаются 12 ч после последнего хода), Claude ни в одной сессии не может сделать `git commit`, `push` и `stash` в этом репозитории (в build — в его worktree). К твоим сообщениям в проекте ревью прикладывается сводка сессии, поэтому Claude не теряет цикл после сжатия контекста. Уведомления о фоновых задачах её не получают: вывод раннера и так содержит всё.

Команды: `/duet` открывает панель, `/duet stop` останавливает идущий раунд (продолжить потом можно через `retry`), `/duet band|toasts|score|sound on|off` включает и выключает части интерфейса (то же делают кнопки в свёрнутом блоке «Настройки» внизу панели), `/duet sound test` или кнопка «▶ Звуки» проигрывает все три сигнала по очереди. Мод ничего не пишет в файлы сессий, только оставляет одну строку следа `.ui-trace.json` для отладки.

## Безопасность

- Codex работает с **полным харнессом**: твой конфиг, модель, effort, все MCP-серверы, apps и скиллы.
- Песочница по умолчанию **наследуется** (`--sandbox inherit`): Codex может то же, что в твоём обычном Codex, например запускать тесты. Явно заданный режим (`read-only`, `workspace-write`, `danger-full-access`) применяется на каждом ходе: `-s` на старте и `-c sandbox_mode=…` на `resume`, потому что у `resume` нет флага `--sandbox`.
- Запрет править файлы на ревью, коммитить и менять внешние системы — это **инструкция в промпте, а не песочница**. С `inherit` и твоим `danger-full-access` у агента без присмотра полный доступ, так что чужой код (внешние PR, скачанные файлы) ревьюй с `--sandbox read-only`.
- **MCP-инструменты песочница не ограничивает.** У ревьюера те же MCP, что и в твоём Codex, включая те, что могут писать во внешние системы, например в боевую базу. Промпт прямо запрещает что-либо менять через любые инструменты, но это защита на уровне инструкции, а не песочницы.
- **Связка ключей и подменённый `HOME` (macOS).** Программа, запущенная с `HOME` во временном каталоге (`claude`, `gh`, помощники git для паролей, `security`), не находит связку ключей macOS, и на каждую попытку входа macOS показывает окно «связка ключей не найдена». Окна висят, пока их не закроешь. В таких окнах жми «Отменить»: «Сбросить настройки по умолчанию» создаёт новую пустую связку ключей вместо твоей. Ссылка на `~/Library/Keychains` окна убирает, но отдаёт программе всю твою связку: её элементы меняются через securityd. Поэтому промпты Codex (build и ревью) и правила для Claude в SKILL.md требуют давать таким программам вход через окружение: `CLAUDE_CODE_OAUTH_TOKEN` (его создаёт `claude setup-token`) или `GH_TOKEN`. Если входа нет, нужно спросить. Такие окна вызывали, например, смоук-запуски `claude -p` в сессии Claude, которая вела сборку; сам Codex ни `claude`, ни `security` не запускал.

## Тесты

```bash
node tests/run.mjs
node tests/mod.mjs
claude plugin test .
claude plugin validate .
```

Запускать из папки плагина. `run.mjs` и `mod.mjs` идут и в GitHub Actions (`.github/workflows/tests.yml`) на macOS и Linux.

`run.mjs` проверяет раннер на фейковом Codex (`tests/fake-codex.mjs`): журнал, споры, эскалацию, `retry`, read-only на `resume`, diff между раундами и политику с причинами решений на английском.

`mod.mjs` транспилирует настоящий `hooks/register.tsx` вместе с его локальными статическими импортами и прогоняет его хуки на заглушке движка (`tests/mod-engine.mjs`). Сессии для него создаёт `duet.mjs` с тем же фейковым Codex. Проверяются панель, строка, футер, тосты, звук, возврат в цикл, защита от коммита и сводка. Языковые тесты проверяют английский по умолчанию, явно выбранные русский и китайский, приоритет локали в `auto`, выбор предпочитаемого языка macOS и английского при ошибке чтения, переводы сообщений и решений для сессии и совпадение ключей трёх таблиц переводов. Для транспиляции нужен esbuild (подойдёт тот, что внутри глобального `tsx`) или `typescript`; путь можно задать через `ESBUILD` или `TYPESCRIPT`. Заглушка ловит ошибки логики, но не ошибки в понимании API: новые вызовы движка сверяй с `claude-code.d.ts` и `claude plugin validate`. Идея взята из plan-progress ([zycck/claude-mods](https://github.com/zycck/claude-mods)).

`tests/pane.test.tsx` рисует панель через тестовый набор самого движка (`claude plugin test`) на поверхностях terminal, desktop и mobile на английском, русском и китайском: таблица элементов каждой поверхности проверяет дерево, чего заглушка не умеет. Сессия ревью лежит в памяти теста; проверяется, что длинные заголовки и пометка о чужой сессии видны целиком, замечание разворачивается, а слова Codex идут как markdown; узкая панель в 44 колонки проверяет переносы и для китайских символов двойной ширины.

## Подводные камни Codex CLI (0.159)

- `codex exec` ждёт EOF на stdin, если stdin не терминал, и молча висит. Раннер передаёт промпт через stdin и закрывает его.
- `codex exec resume` не принимает `--sandbox`, `--cd` и `--color`.
- `-c 'mcp_servers={}'` не отключает MCP: значения сливаются, а не заменяются.
- `codex mcp list --json` печатает env серверов **без маскировки**, включая токены.

## Разработка

Клон в `~/.claude/skills/codex-duet` Claude Code подхватывает сам как `codex-duet@skills-dir`, без установки. Правки доходят до новых сессий. Не ставь при этом тот же плагин из маркетплейса: установленный плагин побеждает одноимённый skills-dir, и клон показывается как «Not loaded».

## Отключить или удалить

```bash
claude plugin disable codex-duet@codex-duet
claude plugin uninstall codex-duet@codex-duet
```

Клон в `~/.claude/skills` отключается так же, с именем `codex-duet@skills-dir`, а удаляется вместе с папкой.
